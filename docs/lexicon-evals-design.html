A lexicon that learns from use, and evals that write themselves.

Prism already OCRs the focused window at refine time. This spec is how we stop missing identifiers that scrolled off, how we never auto-write secrets into the dictionary, and how evals appear from real dictation without anyone pasting JSON.

The job

You dictate code while looking at an agent terminal. ASR splits apply_lexical_hints into “apply lexical hints.” Refine should emit the identifier. You should not have to harvest test cases by hand when that fails.

Three hard rules, unchanged:

  • Pixels never leave the machine. Grok gets strings, not screenshots.
  • OCR never writes refine-dictionary.md by itself.
  • A screen term is used only when the transcript already supports it. Unspoken names stay out.

Do

Local grim. Recency across windows you just focused. Harvest identifiers from the current agent session and repo. Log every take. Mint evals from those logs. Pin a join to the dictionary only when you say so, or after repeated successful joins you confirm.

Do not

OCR both 4K monitors by default. Upload PNGs. Append every OCR token to the persistent dictionary. Dump full window text into context_for_disambiguation_only. Commit personal sentences to git.

What it does today

Recording stops → Parakeet transcribes → voxtype-refine runs. If screen_context = true, it screenshots the focused Hyprland window, OCRs it, keeps code-shaped tokens, sends them with the transcript to Grok, then locally respells near-misses. A 5-minute cache remembers recent tokens. If the whole utterance is identifier-shaped, it can join to snake_case even with an empty OCR list.

Limits you already hit: the shot is the visible rectangle only; it happens after transcription, so you may have scrolled; tesseract drops underscores; a pasted miss pollutes the next shot with spaced English.

Automatic evals

You should never copy a case into refinement-eval.json. The machine already has the pair it needs: what you said, what was on screen, what came out. Evals are a filter over that stream, not a writing assignment.

raw: apply lexical hints. screen: apply_lexical_hints, Hyprland, … out: apply_lexical_hints.

Every dictation already produces this triple. We persist it. That is the only source of evals.

The take log

Path: $XDG_STATE_HOME/voxtype/refine-takes.jsonl. One line per refine. Not in git. Mode 0600.

{
  "t": "2026-09-04T12:40:11Z",
  "raw": "apply lexical hints.",
  "out": "apply_lexical_hints.",
  "ok_lex": true,
  "window": "com.mitchellh.ghostty",
  "screen": ["apply_lexical_hints", "Hyprland"],
  "changed": true
}

Voxtype already prints Post-processed: changed: true/false. The child can write the rest. No extra gesture for logging.

Three minting factories (zero copy-paste)

A. Identifier harvest (local, no API, timer or on refine). From today’s OCR cache plus Claude / Hermes / Codex / Grok session files in the current cwd, run extract_spellings. For each new token, invent the spoken split (apply_lexical_hints → “apply lexical hints”). Run apply_lexical_hints in-process. If it fails, that is a joiner regression and becomes a unit case immediately. If it passes, keep one canonical example in a local set so the shape cannot silently regress. This is how the screen_code_* cases were born, without you typing JSON.

B. Live miss (no gesture). If changed: false and the raw utterance is identifier-shaped and a screen or cache token has the same folded form, mint {transcript: raw, expected: that token, on_screen_spellings: screen}. If two takes within a minute share a fold and the second differs, treat take 1 as spoken and take 2 as expected (self-correction).

C. Optional “wrong” chord. One key after paste. The next dictation or the next typed replacement in the same window is expected. Still no JSON. This is the only human signal, and it is optional because A and B already catch identifier misses.

What is allowed into git

A nightly (or on-demand) voxtype-refine harvest-evals reads the take log and the harvest set, then writes tests/fixtures/refinement-eval.inbox.json. A case is auto-accepted into refinement-eval.json only when all of these hold:

  • expected is a single code token (underscore, hyphen, mixed case, or backtick wrap), length ≤ 128
  • transcript is that token spoken as words, plus optional final punctuation
  • no emails, paths under /home/henny/, or dictionary secrets
  • the name is new

Personal sentences (“um send the report…”) stay in the private log forever. They never become repo evals unless you later promote one on purpose. Identifier cases promote themselves.

Most identifier evals do not need Grok. apply_lexical_hints is the test. Run that on harvest in milliseconds. Call the live provider only for a nightly sample of inbox cases, or when a miss was a Grok-only failure (lexical already had the token and Grok still rewrote it).

OCR and screenshots

Screenshots stay a local grim PNG in a temp fd, unlinked after tesseract. They are not uploaded, not attached to eval JSON, not sent to Grok.

When to shoot

  • Record start. The window you were looking at while you spoke. This is the important new shot. Today we only shoot after ASR, when you have often scrolled to the input.
  • Refine start. Keep the current shot; merge tokens from both.
  • Recency. Keep tokens from the last few focused windows for five minutes (already sketched). Not “every monitor, forever.”

A tiny terminal still yields a tiny shot. Recency plus record-start is how we survive shrink-and-scroll. Full-desktop OCR stays off unless you later add an explicit “focused monitor” flag.

Auto-write in this spec means: auto-write evals and the ephemeral lexicon. It does not mean auto-write the user dictionary. After the same join succeeds three times, the workbench may ask “pin apply_lexical_hints?” Default is no.

Other context

Still a lexicon, not a dump. Candidates, cheapest first:

  • Hyprland window title and class (free).
  • Identifiers in the focused cwd: git ls-files basenames, not file bodies.
  • Current agent session files for that cwd, passed through extract_spellings only.
  • AT-SPI if present.

Do not put full session transcripts, .env, or clipboard contents into Grok. If a harvested token is not a near-miss of the spoken transcript, it is unused.

Work packages

Separate tasks, same repo. Each package has a test you can run without a microphone.

P1 — Take log

scripts/voxtype-refine · no network

After each refine, append one jsonl record (raw, out, screen, window, changed, timestamps). Tests: tempfile path via env; secrets already stripped by extract_spellings stay stripped; file mode 0600.

P2 — Record-start capture

hyprland hook or a tiny helper Voxtype can call without stealing pre_recording_command

On hotkey-down, grim the focused window to a runtime PNG with a generation id. Refine reads it if younger than the recording, OCRs, merges with the post-ASR shot, deletes both. Tests: stale file ignored; missing file is [].

P3 — Recency across recent windows

extend the 5-minute lexicon

Key cache entries by window stableId. Merge last K focused windows. Tests: spoken identifier from window A still joins after focus moves to a tiny window B.

P4 — Session and git harvest

local, cwd-scoped

Pull identifiers from current-agent session files and git ls-files names. Same extract_spellings. Tests: no home paths, no .env, fold-match still required before use.

P5 — Harvest-evals (the frictionless part)

scripts/voxtype-refine harvest-evals

Factories A and B over the take log + session harvest. Auto-accept identifier-only cases into the corpus. Run apply_lexical_hints on the inbox in unit tests (no API). Optional nightly live Grok sample. Tests: a polluted miss mints screen_code_spoken_case_name; a prose sentence does not enter git.

P6 — Confirm-to-pin dictionary

workbench + refine.toml

Count successful joins. Prompt to pin. Never silent append. Tests: dictionary file unchanged until confirm.

P1 and P5 are the eval answer. P2 and P3 are the “tiny / scrolled window” answer. P4 is extra identifiers without more OCR. P6 is the only dictionary write, and it is not automatic.
